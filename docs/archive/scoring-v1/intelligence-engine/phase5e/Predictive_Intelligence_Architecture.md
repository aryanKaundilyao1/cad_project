# Predictive Intelligence Architecture (Phase 5E)

## Philosophy
No single machine learning model perfectly captures reality. 
- **Logistic Regression** is great at finding linear relationships but struggles with complex interactions.
- **Gradient Boosting (GBM)** is excellent at capturing non-linear behavior but can overfit to noise.
- **Bayesian Updating** excels in sparse-data environments by building on known priors (WOE) but lacks the multivariate interaction awareness of a GBM.

Therefore, JAS CONNECT uses an **Ensemble Engine**. We train multiple distinct models, let them independently score the opportunity, and then mathematically blend their answers.

## Architecture

### 1. The Sub-Models
- **Bayesian Probability Engine:** Calculates Posterior Odds using the Bayes Factors generated in Phase 5C.
- **Logistic Regression Engine:** Fits a parametric curve using engineered features.
- **Gradient Boosting Engine:** A non-linear decision tree ensemble (e.g. XGBoost / LightGBM).

*(Note: In the initial rollout, Logistic and GBM are architected as simulated mathematical wrappers. When sufficient terminal outcome data is generated by Phase 5A, Python-based ML runners can be plugged directly into these interfaces).*

### 2. The Ensemble Engine
Blends the sub-models using configurable weights.
`P_final = (W_bayes * P_bayes) + (W_logistic * P_logistic) + (W_gbm * P_gbm)`

### 3. The Confidence Engine
A probability is useless without a measure of certainty. The Confidence Engine evaluates:
- **Model Agreement:** Do all three models predict ~70%, or does one predict 20% and another 95%? High variance lowers confidence.
- **Data Completeness:** How many signals triggered? 
- **Output:** Returns a Confidence Score (e.g., 88%) and a Credible Interval (e.g., ±4%).

### 4. Drift Detection
Models degrade as market conditions change.
- **Prediction Drift:** Are we suddenly predicting higher probabilities than usual?
- **Feature Drift:** Has the underlying distribution of signals changed (e.g. suddenly everyone is downloading specs)?
- **Action:** Triggers an alert in the `model_drift_alerts` table to prompt retraining.
